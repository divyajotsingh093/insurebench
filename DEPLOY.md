# Deploying InsureBench (GitHub + Vercel)

## 1. Vercel project (leaderboard + API)

1. Import the GitHub repo in Vercel.
2. **Set Root Directory = `web`** (Project Settings, Build & Deployment). Vercel then detects Next.js; `web/vercel.json`
   pins the framework and commands. There is no repo-root `vercel.json`, because the root directory setting is a project setting and cannot be set in a file.
   - CLI alternative: `cd web && vercel link && vercel deploy`.
3. No environment variables are required. Without `BLOB_READ_WRITE_TOKEN`, the app serves the bundled
   `web/data/leaderboard.json` and `/api/submit` validates but does not store submissions (HTTP 202 `stored:false`).
4. Optional: create a **Vercel Blob** store and connect it to the project. That sets `BLOB_READ_WRITE_TOKEN`. Then:
   - `GET /api/results` and the pages read `results/leaderboard.json` from Blob (revalidated every 5 minutes),
   - `POST /api/submit` stores validated dev-split traces under `submissions/` (private access).

Local check: `cd web && npm install && npm run build` (the prebuild step fails if anything gold-like is in `web/data`).

## 2. GitHub Actions sweep (`.github/workflows/sweep.yml`)

Manual `workflow_dispatch` with these inputs: `suites`, `models` (`roster`, `roster:N` or a comma list), `harnesses`, `k`,
`max_usd`, `split`. The defaults are a cheap smoke run: dev split, `roster:3`, `react_raw`, k=1, a $2 cap.

Repository secrets:

| Secret | Needed for |
|---|---|
| `OPENROUTER_API_KEY` | every model run (required) |
| `BLOB_READ_WRITE_TOKEN` | optional: upload `leaderboard.json` to Blob instead of committing it |
| `INSUREBENCH_PRIVATE_SEED` | official hidden test split (`split=test`) |

Flow: install, then `estimate`, then `sweep --max-usd`, then `report`, then upload artifacts. After that, either the Blob upload (the site
picks it up within 5 minutes) or a commit of `results/leaderboard.json` and `web/data/leaderboard.json` (dev only), which
triggers a Vercel redeploy.

## 3. What must never be public

- `data/gold_hidden/`: gitignored. With `INSUREBENCH_PRIVATE_SEED` set, the test gold can only be regenerated by holders of the secret.
- Per-case test results (`results/runs/*__test/results.jsonl`) contain gold decisions and are gitignored. Only aggregate
  `summary.json` files are committed.
- `.env*` files are gitignored. Use Vercel/GitHub secrets.

## 4. Vercel Sandbox (future)

See `scripts/run_in_sandbox.md`. The plan is to run community-submitted harness code in isolated microVMs. Not implemented in v0.
